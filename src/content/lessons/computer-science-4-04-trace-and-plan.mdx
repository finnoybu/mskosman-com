**Standards covered (2024 Virginia Computer Science SOL)**

- **4.AP.2** The student will plan and implement algorithms that consist of sequencing, loops, variables, user input, and conditional control structures using a block-based programming language.
  - c. Read and explain a design document to trace and predict an algorithm using plain language, pseudocode, or diagrams.
  - d. Create a design document to plan an algorithm using plain language, pseudocode, or diagrams.

## Prep

- Write this plan on paper: SET score TO 0. ASK "What is your name?" and store the answer in playerName. REPEAT 3 TIMES: ASK a question. IF the answer is correct THEN CHANGE score BY 1. SAY playerName and score.

## Warm-up (3 minutes)

Show the prepared plan. Ask, "Without building it, can you tell me what this program would do?"

## Direct Instruction (5 minutes)

- Define trace: to follow an algorithm one step at a time, keeping track of what changes.
- Model tracing the first lines, updating the slips in the variable boxes as you go.
- Predict the final output for a player who gets two answers right.
- Review the forms a design document can take: plain language, pseudocode, or a diagram.
- Point out what makes this plan easy to trace: one action per line, named variables, and indented steps inside the loop.

## Guided Practice (7 minutes)

1. The student traces the rest of the plan and states the output.
2. Trace again for a player who gets every answer wrong.
3. Together, redraw part of the plan as a flowchart.
4. Brainstorm ideas for the student's own program that uses a variable and user input.

## Independent Practice / Quick Check (5 minutes)

The student writes a design document for their idea, in pseudocode or as a diagram, including a variable, user input, and a conditional. Then the student traces it once to check it.

Look for:
- The student follows the steps in order and tracks variable values.
- The prediction matches what the plan would do.
- The student's plan is clear enough for someone else to trace.

## Differentiation

**For students needing support**
- Trace a plan with no loop first.
- Provide a template with SET, ASK, IF, and SAY lines to fill in.

**For students ready for more**
- Trace a plan that contains a mistake and find it.
- Write the same plan as pseudocode and as a flowchart.

## Extensions

- Trade plans with someone and trace each other's.
- Write pseudocode for the scoring rules of a favorite game.

## Notes for Parent/Instructor

- Tracing on paper before building saves a great deal of debugging later.
- Keep the student's design document for Lesson 6.
