**Standards covered (2024 Virginia Computer Science SOL)**

- **8.DA.1** The student will create computational models to simulate events or represent phenomena.
  - c. Refine computational models based on generated outcomes.
- **8.DA.2** The student will evaluate computational models to analyze patterns and make recommendations or predictions.
  - b. Analyze patterns and interpret data generated by computational models and simulations, identifying meaningful patterns and relationships.

## Prep

- Prepare a run log: run number, what was changed, what happened, what was learned.

## Warm-up (3 minutes)

Ask, "Your simulation shows a population of negative 40 rabbits. What does that tell you about the model?"

## Direct Instruction (4 minutes)

- Explain refining from generated outcomes: run the model, look for results that are impossible or unrealistic, find the rule responsible, and adjust it.
- Introduce checks: do values stay in sensible ranges, does the model behave sensibly at extremes, and does it match what is known about the real system?
- Explain analyzing generated data: look for trends, cycles, turning points, stable states, and thresholds where behavior changes.
- Explain relationships: how changing one input changes an output. Change one input at a time.

## Guided Practice (9 minutes)

1. The student runs the model and records the outcome in the log.
2. Identify an unrealistic result and refine the rule causing it.
3. Run it with three different values of one input and chart the outputs.
4. Describe the pattern and the relationship found.

## Independent Practice / Quick Check (4 minutes)

The student performs a second refinement, logs it, and writes a paragraph interpreting the model's output: the main pattern, one relationship between variables, and one limitation.

Look for:
- Refinements respond to specific outcomes.
- Inputs are varied one at a time.
- Patterns and relationships are described with reference to data.

## Differentiation

**For students needing support**
- Refine one rule.
- Vary one input across two values.

**For students ready for more**
- Find a threshold at which the system's behavior changes sharply.
- Compare the model's output with real data, if available.

## Extensions

- Use the model to answer a what-if question.
- Explain the model's main pattern to someone unfamiliar with it.

## Notes for Parent/Instructor

- Impossible outputs are useful. They show exactly where the model is wrong.
- Changing several inputs at once makes relationships impossible to see.
