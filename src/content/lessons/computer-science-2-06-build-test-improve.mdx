**Standards covered (2024 Virginia Computer Science SOL)**

- **2.AP.3** The student will use the iterative design process to create, test, and debug a program containing events and loops in a block-based programming tool.
  - d. Create and test a program that uses events and loops.
  - e. Revise and improve a program to produce desired outcomes.

## Prep

- Have the student's design document ready.
- Check that the tool opens to a new, empty project.

## Warm-up (2 minutes)

Reread the design document together. Ask, "What event starts your program? Is there anything that repeats?"

## Direct Instruction (4 minutes)

- Explain the cycle: build a little, test it, improve it, and test again. "Programmers call this the iterative design process. Iterative means we repeat the cycle."
- Show where the event blocks and the repeat block are in the tool.
- Model building the first two steps of a plan, then running it right away.
- Model a revision: "It moved too far. I will change the number and test again."

## Guided Practice (8 minutes)

1. The student builds the first part of their plan: the event and one action.
2. Test it. Ask, "What happened? Is that what the plan says?"
3. The student adds the loop and tests again.
4. When something is wrong, the student points to the block that needs to change, changes it, and retests.

## Independent Practice / Quick Check (6 minutes)

The student finishes the program alone, tests it, makes at least one improvement, and then shows you the final version while explaining what changed and why.

Look for:
- The program contains an event and a loop.
- The student tests after building and not only at the end.
- The student makes a specific revision and can explain it.

## Differentiation

**For students needing support**
- Build from a three-step plan.
- Sit beside the student and name each block as they place it.

**For students ready for more**
- Add a second character with its own event.
- Ask the student to make the program shorter by using a loop where actions repeat.

## Extensions

- Share the program with a family member and ask for one idea to improve it.
- Write a new design document and build it another day.

## Notes for Parent/Instructor

- Expect the first version not to work as planned. That is the point of the cycle.
- Ask "What did it do?" before "What is wrong?" so the student describes the result first.
