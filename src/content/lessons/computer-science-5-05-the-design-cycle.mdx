**Standards covered (2024 Virginia Computer Science SOL)**

- **5.AP.3** The student will use the iterative design process to create, test, and debug programs containing sequencing, loops, variables, user inputs, nested conditional control structures, and two-way branching conditional control structures in a block-based programming tool.
  - a. Use accurate terminology to describe and explain the iterative design process.
  - b. Create and test programs that consist of sequencing, loops, variables, user inputs, nested conditional control structures, and two-way branching conditional control structures.

## Prep

- Write the stages on a card: define the problem, plan, build, test, evaluate, revise, and repeat.
- Check how the tool nests one if-else block inside another.

## Warm-up (3 minutes)

Ask, "Does anyone get a program right on the first try? What do programmers do about that?"

## Direct Instruction (4 minutes)

- Name each stage of the iterative design process and say what happens in it. Iterative means the cycle repeats.
- Use the accurate terms: algorithm, program, test, bug, debug, revise.
- Show an if-else block and how a second one fits inside a branch.
- Agree to say which stage you are in as you work.

## Guided Practice (9 minutes)

1. The student builds the input and variables from the plan and tests.
2. Add the outer conditional. Test both branches.
3. Nest the inner conditional. Test every outcome.
4. Add the loop. At each step the student names the stage.

## Independent Practice / Quick Check (4 minutes)

The student completes the program and explains the design cycle in their own words, pointing to a moment in today's work for each stage.

Look for:
- Stages are named and explained accurately.
- The program includes every required element.
- Each branch of the nested conditional has been tested.

## Differentiation

**For students needing support**
- Build the guessing game from the model plan.
- Keep the stage card in view and point as you go.

**For students ready for more**
- Add a counter for the number of attempts.
- Add a second input that changes how the program behaves.

## Extensions

- Draw the cycle as a poster with examples from the project.
- Let someone test the program and note what confuses them.

## Notes for Parent/Instructor

- Accurate terminology is the new expectation. Use the terms yourself.
- Count the outcomes of the nested conditional and test that many cases.
