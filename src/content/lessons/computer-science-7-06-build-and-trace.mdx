**Standards covered (2024 Virginia Computer Science SOL)**

- **7.AP.3** The student will use the iterative design process to create, test, and debug programs using a block-based or text-based programming language.
  - a. Create and test programs that contain multiple control structures.
  - b. Trace and predict outcomes of programs.

## Warm-up (2 minutes)

Reread the plan. Ask, "Which part will you build first, and how will you know that part works before going on?"

## Direct Instruction (3 minutes)

- Set a build order: write and test the function alone, then the main algorithm.
- Review control structures: sequence, loops, conditionals, and function calls.
- Model a trace table that includes a function call: record the values passed in and the result.
- Remind the student to test after each addition.

## Guided Practice (10 minutes)

1. The student writes the function and tests it with two sets of values.
2. Build the main loop that calls it.
3. Add the conditional.
4. Trace one full pass on paper and compare with the program.

## Independent Practice / Quick Check (5 minutes)

The student completes the program, traces it for a new set of inputs, predicts the outcome, and runs it to check.

Look for:
- The program has several control structures and a function.
- The function is tested on its own.
- The trace matches the run.

## Differentiation

**For students needing support**
- Build the starry sky example.
- Trace with the function treated as one step.

**For students ready for more**
- Add a second function.
- Trace into the function line by line.

## Extensions

- Add a feature and update the plan to match.
- Explain the program to someone using the trace table.

## Notes for Parent/Instructor

- Testing a function alone before using it is a professional habit.
- This lesson and the next form one design cycle.
