**Standards covered (2024 Virginia Computer Science SOL)**

- **3.AP.3** The student will use the iterative design process to create, test, and debug programs containing events, loops, and conditional structures in a block-based programming tool.
  - a. Create and test programs that consist of events, loops, and conditional structures.

## Prep

- Try the tool yourself and locate the event blocks, the repeat or forever block, and the if-then and if-then-else blocks.
- Build a tiny sample: when the program starts, repeat, and if the character touches the edge, turn around.

## Warm-up (2 minutes)

Show your sample running. Ask, "Where do you think the program is making a decision?"

## Direct Instruction (5 minutes)

- Open your sample and point out the three structures: the event block on top, the loop block wrapped around the actions, and the conditional block inside.
- Read it aloud as pseudocode.
- Show how a condition block fits into the slot of the if block.
- Remind the student of the cycle: build a little, test, then build more.

## Guided Practice (8 minutes)

1. The student starts a new project and adds the event from their design document.
2. Add the loop and one action. Test.
3. Add the conditional from the plan. Test both outcomes: make the condition true, then false.
4. Ask after each test, "What happened? Does it match the plan?"

## Independent Practice / Quick Check (5 minutes)

The student completes the program so that it follows the design document, then demonstrates it and points to the event, the loop, and the conditional.

Look for:
- All three structures are present and used for a purpose.
- The student tests both branches of the conditional.
- The student tests in small steps.

## Differentiation

**For students needing support**
- Provide a starter project with the event and loop in place so the student adds only the conditional.
- Use if-then without else.

**For students ready for more**
- Add a second conditional.
- Use a sensing block, such as a key press, as the condition.

## Extensions

- Change the program so the conditional does something different and predict the result first.
- Show the project to a family member and explain how it decides.

## Notes for Parent/Instructor

- If the tool from Grade 2 has no conditional blocks, this is the time to move to one that does.
- Testing both outcomes of a conditional is a habit worth insisting on.
