**Standards covered (2024 Virginia Computer Science SOL)**

- **6.AP.2** The student will plan and implement algorithms that include conditional control structures and collection of numeric data using a block-based or text-based tool.
  - d. Read and write programs that contain nested conditional control structures.
- **6.AP.3** The student will use the iterative design process to create, test, and debug programs using a block-based or text-based programming language.
  - a. Create and test programs that uses multiple conditional control structures.

## Prep

- Write a short program with a nested conditional for the student to read, such as the shipping fee example.

## Warm-up (3 minutes)

Show the decision tree from Lesson 3. Ask, "How many conditionals would a program need to make this decision?"

## Direct Instruction (4 minutes)

- Read your sample program together. Match each conditional to a node of a decision tree.
- Point out structure: indentation in text-based code, or blocks inside blocks, shows what is nested.
- Distinguish nested conditionals, where one is inside another, from a series of separate conditionals that are each checked.
- Plan tests: one input for every leaf of the tree.

## Guided Practice (9 minutes)

1. The student translates the first question of their tree into a conditional and tests it.
2. Add the nested conditionals for one branch. Test.
3. Complete the remaining branches.
4. Fill in the test table: input, expected outcome, actual outcome.

## Independent Practice / Quick Check (4 minutes)

The student adds one separate conditional that applies regardless of the path, such as a discount, and tests the program for every leaf of the tree.

Look for:
- Nesting in the program matches the tree.
- The program uses more than one conditional structure.
- Every path is tested.

## Differentiation

**For students needing support**
- Use a tree with two levels.
- Translate one branch together.

**For students ready for more**
- Combine two nested conditionals into one using AND and compare readability.
- Add input checking for values that make no sense.

## Extensions

- Turn a second decision tree into a program.
- Have someone else use the program and try to find an untested path.

## Notes for Parent/Instructor

- A decision tree is the design document for this program.
- The number of leaves is the minimum number of tests.
