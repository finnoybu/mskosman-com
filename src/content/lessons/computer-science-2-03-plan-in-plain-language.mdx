**Standards covered (2024 Virginia Computer Science SOL)**

- **2.AP.2** The student will plan and implement algorithms that consists of events and loops using a block-based programming language.
  - a. Plan and create a design document to guide the construction of a program using plain language or pseudocode.

## Warm-up (2 minutes)

Ask, "If you wanted a cartoon cat on a screen to dance, what would you tell it to do?" Let the student describe it freely.

## Direct Instruction (5 minutes)

- Explain: "Before programmers build, they write a plan. A plan for a program is a design document."
- Introduce pseudocode: "Pseudocode is a plan written in short, plain sentences. It is not real code. Anyone can read it."
- Model a design document with three parts: Goal (what the program should do), Characters and setting, and Steps in order.
- Write the steps as pseudocode: WHEN the cat is tapped. Move right. Jump. Say hello. REPEAT the jump 3 times.
- Point out the features: one action per line, in order, with the event first.

## Guided Practice (6 minutes)

1. Choose a new idea together, such as a fish that swims across the screen when the program starts.
2. Write the goal in one sentence.
3. The student dictates or writes the steps, one per line.
4. Read the plan back. Ask, "Could someone build this from our plan alone?" Fix anything unclear.

## Independent Practice / Quick Check (4 minutes)

The student writes a design document for their own program idea with a goal and at least four steps in plain language. Keep it for Lesson 6.

Look for:
- The plan states what the program should do.
- Steps are written one per line in a workable order.
- Another person could follow the plan without asking questions.

## Differentiation

**For students needing support**
- Provide a template with the headings Goal and Steps already written.
- Let the student draw each step and dictate the words.

**For students ready for more**
- Include a repeated step and an event in the pseudocode.
- Write two different plans for the same goal.

## Extensions

- Write pseudocode for a real routine, such as making a sandwich, and see whether a family member can follow it.
- Add drawings to turn the design document into a storyboard.

## Notes for Parent/Instructor

- Kindergarten and Grade 1 design documents were drawings. Grade 2 moves to written plain language.
- Do not worry about matching real block names yet. The skill is planning clearly before building.
