**Standards covered (2024 Virginia Computer Science SOL)**

- **4.AP.3** The student will use the iterative design process to create, test, and debug programs containing sequencing, loops, variables, user inputs, and conditional control structures in a block-based programming tool.
  - a. Create and test programs that consist of sequencing, loops, variables, user inputs, and conditional control structures.
  - c. Trace and predict the value of variables that change over the course of the program’s runtime.

## Prep

- Locate the block that asks a question and waits for an answer.
- Draw a trace table with columns: step, what happened, value of the variable.

## Warm-up (2 minutes)

Reread the design document. Ask, "What will the user type or click? What will the program remember?"

## Direct Instruction (4 minutes)

- Show the ask block and where the answer is stored.
- Show a conditional that compares the answer with the correct value.
- Model a trace table: before running, write the variable's expected value after each step.
- Remind the student to build and test in small pieces.

## Guided Practice (9 minutes)

1. The student builds the opening: initialize the variable and ask for input.
2. Add the conditional that changes the variable when the answer is correct. Test with a right and a wrong answer.
3. Wrap the question in a loop or add more questions.
4. Fill in the trace table for one run, then run the program and compare.

## Independent Practice / Quick Check (5 minutes)

The student finishes the program and predicts in the trace table the final value of the variable for a set of answers you choose, then runs it to check.

Look for:
- The program contains all five elements and runs.
- The student tests with different inputs.
- Predicted variable values match the actual run.

## Differentiation

**For students needing support**
- Build a one-question quiz.
- Fill in the trace table together while the program is paused between steps.

**For students ready for more**
- Add a second variable that tracks wrong answers.
- Ask for the user's name and use it in the feedback.

## Extensions

- Let family members try the program and watch what they type.
- Add a high-score message using a conditional.

## Notes for Parent/Instructor

- Sequencing means the blocks are in a deliberate order. Ask why each block is where it is.
- The trace table is the paper version of watching a variable change during runtime.
