**Standards covered (2024 Virginia Computer Science SOL)**

- **2.AP.3** The student will use the iterative design process to create, test, and debug a program containing events and loops in a block-based programming tool.
  - a. Define program.
  - b. Read and interpret a program expressed in a block-based programming language.
  - c. Analyze and describe the results of a program.

## Prep

- Install the tool and try it yourself for ten minutes.
- Build and save a short program: a start event, a move block inside a repeat block set to 4, and a sound or say block at the end.

## Warm-up (3 minutes)

Ask, "How does a game know what to do when you tap the screen?" Take ideas. Then say, "Someone wrote instructions for it."

## Direct Instruction (5 minutes)

- Define: "A program is a set of instructions, written in a language a computer understands, that tells the computer what to do."
- Connect to earlier work: an algorithm is the plan, and a program is the plan written for the computer.
- Open your saved program without running it. Explain that in a block-based language each block is one instruction, and blocks are read in order from the start.
- Point to each block and say its job: the event block that starts the program, the repeat block that loops, the action blocks inside it.
- Model a prediction: "I think the character will move four times and then make a sound."

## Guided Practice (6 minutes)

1. The student reads the program aloud block by block in their own words.
2. The student predicts what will happen and writes or draws the prediction.
3. Run the program. Ask, "What did it do? Did it match your prediction?"
4. Change one number in the repeat block. The student predicts again, then runs it.

## Independent Practice / Quick Check (5 minutes)

Show a second short program you change on the spot (swap two blocks or change the event). The student tells you what a program is, reads this one aloud, predicts the result, runs it, and describes what happened.

Look for:
- The student defines program in their own words.
- The student reads blocks in order and names the event and the loop.
- The student describes the actual result and compares it to the prediction.

## Differentiation

**For students needing support**
- Use a program with three blocks and no loop first.
- Act out each block with the body before running it.

**For students ready for more**
- Read a program with two characters and predict how they interact.
- Explain why two programs that look different do the same thing.

## Extensions

- Explore sample projects in the tool and read their blocks before running them.
- Write pseudocode that matches a program you read.

## Notes for Parent/Instructor

- The lesson is about reading, not building. Resist letting the student start creating until Lesson 6.
- Any block-based tool for early readers works. Use the same one all year so the blocks become familiar.
